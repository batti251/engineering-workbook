# EngineeringWorkbook

A personal knowledge platform where I document, connect and apply what I learn about software engineering while continously developing the platform itself.


## My Vision
During my journey, to learn to code and getting into the world of software development, I've noticed something:
Writing self-written notes about code syntax and use-cases, relationships between two systems, or an overview about a software pattern, are not growing well in Word-Documents- or note-files.
And it feels not right to document code and code-related topics outside an IDE.

So I made a decision.

Nothing will describe and teach me better than a long-term project that documents all software related topics and beyond. 

As the project grows, I will grow as wwell

It should not be just another coding-project, some CRUD-Functions, leaving some notes and keep it as MVP.

This project will guide me through many steps of a long-term development project.
Architecture, technical decisions, technical depth, tests...


It should not be another MDN, or another documentation site for a framework.
It should not describe how to write the code syntactically, but how to use it in real world situations. 
It should explain in **my words**, in **my understanding** how things work and how to use it productively. 

As a result, the application is not only a knowledge base  — its architecture also reflects my growth as an engineer.
